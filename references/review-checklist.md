# Review checklist

Use after running `scripts/check_resume.py`. The script covers the mechanical items; this list is for the judgement calls. Go through every section, then write the report in the format at the bottom.

## A. First impression (the 10-second skim)
- Can a reader tell within 10 seconds who this is, their level (student / PhD / engineer), and their field?
- Is the most impressive thing (publication, top award, best job) visible on page 1, top half?
- Is the length right for the target (see writing-rules §4)?
- Does section order match the target? (Academic: Education → Publications → Research. Industry: Education → Experience → Projects → Skills.)

## B. Content, entry by entry
- Does each entry have: title, location if applicable, dates, role/degree line, 2–5 bullets?
- Does each bullet follow action + method + result? Which bullets are only a task description with no result?
- Is at least one bullet per entry quantified? Where a number is missing, what specific number could the owner likely supply (accuracy, speed-up, dataset size, users, cost, team size)?
- Overclaims or vague claims ("high-precision", "significantly", "unexplored area") without evidence?
- Does the owner's role come through (led / built / co-designed), or is it hidden behind team language?
- Redundancy: the same fact repeated across publications, research and experience?
- Stale or odd items: outdated status ("under review" from long ago), old test scores, very early achievements that crowd out recent ones.

## C. Consistency
- Tense (past for finished, present for ongoing), date format, location format, punctuation at bullet ends, capitalization of titles.
- Publication list: same citation style for every item; owner's name bolded every time.
- Skills section agrees with what the bullets show.

## D. Language
- Grammar, articles, prepositions, Chinese-English patterns (writing-rules §5).
- Repeated opening verbs.
- Jargon a recruiter would not decode, with no plain-language anchor.

## E. Fit to target (only when a JD or target role is given)
- Top 5–10 requirements of the JD: which are clearly evidenced, which are partially evidenced, which are missing?
- Keywords from the JD that are true for the owner but absent from the resume.
- What to move up, compress, or cut for this role.

## Report format

Write the report in the language the user writes to you in (bullet text quoted in its original language). Order by impact, not by position in the document:

1. **Overall** — 2–3 sentences: level, strongest points, the single biggest problem.
2. **Must fix** — errors that hurt credibility: typos, wrong contact info, inconsistent dates, factual/format errors. Each with location and the exact fix.
3. **Should improve** — content weaknesses: unquantified or vague bullets, missing role titles, weak verbs, overclaims. For each, quote the original and give a rewritten version; where a number is needed, show a placeholder and ask for it.
4. **Optional** — structure/order/length suggestions and tailoring ideas.
5. **Questions for you** — the facts you need from the owner to make the "should improve" items real.

Keep suggestions within the owner's format and structure unless they asked for a restructure. Never present a rewritten bullet containing a number the owner didn't give without marking it as a placeholder.

If the user wants the feedback inside the document, add Word comments anchored to the relevant text (see SKILL.md, "Annotated output").
